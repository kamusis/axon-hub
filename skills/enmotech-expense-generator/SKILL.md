# 云和恩墨报销明细生成器与 CloudCC 导入闭环

## 工作原理

用户提供一个发票目录路径（包含 PDF、JPG、PNG 发票或截图），Agent 自动完成从票据识别到系统导入的全流程闭环：

```
发票目录 (PDF/图片) 
   ↓ (pdfplumber 提取文本 / 多模态图像识别)
提取票面要素 (金额、日期、商户、车次、酒店等)
   ↓ (构建时间线、归并滴滴行程单等补充文件、自动核算差旅与住宿补助)
自动匹配 CloudCC 出差申请与项目代码 (cloudcc personnel businesstrip)
   ↓
生成官方标准 invoices.json
   ↓ (reimbursement-validate-invoices.py & reimbursement-fill-invoice.py)
填充标准 Excel 模板 (报销单批量导入_已填充.xlsx)
   ↓
展示汇总表格供用户口述微调或确认
   ↓ (用户确认导入)
CloudCC 一键导入 (cloudcc reimbursement import)
   ↓
批量挂载发票附件 (cloudcc reimbursement upload-attachment)
```

核心思路：**文件名 = 上下文线索，文件内容 = 数据来源，CLI = 业务闭环**。

---

## 字段规范

字段定义及映射规则参照 `references/field_definitions.md` 与 `references/reimbursement-field-mapping.md`。

**标准 invoices.json 字段定义：**

| JSON 字段 | 说明 | 类型 | 来源 |
|:---|:---|:---|:---|
| `qsrq` | 费用发生起始日期 | YYYY-MM-DD | 票面提取 / 行程合理性推断 |
| `jsrq` | 费用发生结束日期 | YYYY-MM-DD | 票面提取 / 行程合理性推断 |
| `bxlx` | 报销类型 | 枚举值 | 默认 `日常费用`，差旅亦可选 `实施费用` / `销售费用` |
| `fylx` | 费用类型 | 枚举值 | 参照 `references/reimbursement-expense-types.md` |
| `fysm` | 费用说明 | 字符串 | 规范：`{文件名}：{服务/货物}（{销售方}，发票号：{XXX}）` |
| `bxje` | 报销金额 | 浮点数 | 票面价税合计，纯数字，两位小数 |
| `fapiaohao` | 发票号码 | 字符串 | 18-20 位发票号码，无票或补助填 `""` |
| `xmmc` | 项目名称 | 字符串 | 优先从出差单关联项目匹配，或默认 `2026年_数据库管理服务产品群直属_ID` |
| `ccsqv1` | 出差申请编号 | 字符串 | 优先从 `cloudcc personnel businesstrip` 自动匹配，非出差留空 `""` |
| `xshdbh` | 销售活动编号 | 字符串 | 选填，无则填 `""` |
| `bgd` | 报工单号 | 字符串 | 选填，无则填 `""` |
| `wpgzsq` | 外派工作申请 | 字符串 | 选填，无则填 `""` |

## 工作流

### Step 1: 解析请求与上下文匹配

1. **获取目录路径**：从用户输入中提取包含发票的目录路径（如 `~/Documents/invoices/2026-09-出差`）。
2. **检查 CLI 登录状态**：
   ```bash
   cloudcc auth status
   ```
   若未登录，引导用户执行 `cloudcc auth send-code` 与 `cloudcc auth login`。
3. **出差申请与项目智能匹配（无需强制追问）**：
   - 扫描用户输入：若用户已显式指定出差单号或项目，直接采用。
   - 若未提供：先快速扫描发票的日期范围，调用出差查询命令：
     ```bash
     cloudcc personnel businesstrip --keyword "<当前用户名>" --ccksrq-from <最早日期> --ccksrq-to <最晚日期> --output json
     ```
   - 若命中该日期窗口内已审批通过的出差单，自动提取 `name`（出差申请号，如 `202609167131`）与 `xiangmu`（项目名称，如 `2026年_东西大区服务部直属_ID`），并在汇总展示时告知用户；
   - 若命中多条，列出供用户简要确认选择；
   - 若非出差（如市内办公用品、日常团建），`ccsqv1` 设为空字符串 `""`，项目采用默认值或用户指定值。

---

### Step 2: 扫描目录

列出目录中所有受支持的发票文件：
```bash
python scripts/extract_invoice_text.py <目录路径>
```

**处理规范**：
- 支持格式：`.pdf`, `.png`, `.jpg`, `.jpeg`, `.bmp`
- 仅处理指定根目录文件，不递归子目录
- 过滤无关文件（`.DS_Store`, `Thumbs.db` 等）

---

### Step 3: 逐文件提取信息

#### 3.1 文件读取策略
* **PDF 电子发票**：优先由 `scripts/extract_invoice_text.py` 通过 `pdfplumber` 直接提取文本层（速度快、精度最高）。
* **扫描件 PDF / 图片发票**：脚本自动将 PDF 转为 PNG，或对图片进行预处理，Agent 使用多模态图像读取工具读取票面内容。

#### 3.2 提取关键信息
* **金额**：提取价税合计（纯数字，保留两位小数）。
* **日期**：发票开票日期、乘车日期、入住/退房日期。
* **商家与明细**：销售方公司名、航班/车次号、酒店名、服务或货物名称。
* **发票号**：18-20 位发票号码。

---

### Step 4: 行程时间线构建、单据归并与出差补助核算

#### 4.1 行程时间线构建
按时间升序梳理所有交通票据（机票、高铁票、长途车票），确定在各城市的行程起止窗口。

#### 4.2 日期合理性校验
餐费、住宿、市内打车等可能在出差结束后补开发票。若开票日期晚于出差返程日，但城市在行程窗口内，应将实际发生日期回溯推断为在当地出差期间。

#### 4.3 补充单据归并（避免重复报销）
* **滴滴行程单 vs 滴滴电子发票**：仅以电子发票作为报销记录，行程单作为补充说明（用于完善起止地点说明），不单独生成记录，单据数不递增。
* **酒店明细清单**：作为住宿发票补充，不单独生成记录。

#### 4.4 出差补助自动核算（无票支出）
对于差旅报销，根据出差起止天数自动生成两条独立补助记录（费用类型均为 `差旅费-补助`，单据数填 `0`，`fapiaohao` 填 `""`）：
1. **差旅补助**：天数 × 100 元/天（按首末交通票据界定出差天数，当天往返计 1 天）。
2. **住宿补助**：（出差天数 - 1 - 有酒店发票住宿晚数）× 100 元/天（如全程住酒店则天数为 0，不生成此项）。
* 费用说明格式：`{N}天出差补助`、`{M}天无酒店住宿补助`。

---

### Step 5: 生成官方标准 invoices.json

将所有明细（含发票与自动计算的补助）组织为 JSON 数组，保存至发票目录下的 `invoices.json`：

```json
[
  {
    "qsrq": "2026-09-16",
    "jsrq": "2026-09-18",
    "bxlx": "日常费用",
    "fylx": "差旅费-机票",
    "fysm": "上海-石家庄机票（春秋航空，发票号：26318781111033962073）",
    "bxje": 1200.00,
    "fapiaohao": "26318781111033962073",
    "xmmc": "2026年_东西大区服务部直属_ID",
    "ccsqv1": "202609167131",
    "xshdbh": "",
    "bgd": "",
    "wpgzsq": ""
  }
]
```

---

### Step 6: 校验与填充官方 Excel 模板

执行官方验证与填充脚本：

```bash
# 1. 验证 JSON 完整性与合理性
python scripts/reimbursement-validate-invoices.py <目录>/invoices.json

# 2. 填充数据到官方 Excel 模板
python scripts/reimbursement-fill-invoice.py assets/reimbursement-template.xlsx --from-file <目录>/invoices.json --output <目录>/报销单批量导入_已填充.xlsx
```

---

### Step 7: 结果展示与人工确认

在对话中向用户展示结构化汇总卡片：

```markdown
### 📊 报销明细汇总与待确认
- **发票文件数**：5 个
- **报销明细条数**：6 条（含 1 条自动核算差旅补助）
- **合计报销金额**：¥ 2,845.50
- **关联出差单**：202609167131（上海 → 石家庄）
- **关联项目**：2026年_东西大区服务部直属_ID

| # | 费用类型 | 金额 (元) | 起止日期 | 发票号 | 费用说明与来源文件 | 校验提示 |
|---|---|---|---|---|---|---|
| 1 | 差旅费-机票 | 1,200.00 | 09-16 ~ 09-16 | 263187... | 上海-石家庄机票（机票.pdf） | ✅ 通过 |
| 2 | 差旅费-住宿 | 545.50 | 09-16 ~ 09-18 | 263187... | 石家庄希尔顿2晚（住宿.pdf） | ✅ 通过 |
| 3 | 差旅费-补助 | 300.00 | 09-16 ~ 09-18 | - | 3天出差补助（自动核算） | ℹ️ 自动计算 |

> 📁 已生成标准文件：`报销单批量导入_已填充.xlsx`
> 请检查上方明细。如有误可直接口述修改（如“第2条金额改为500”）；确认无误请回复 **“确认导入”**。
```

**交互规则**：
* 必须等待用户明确确认，**未收到“确认导入”绝不执行后续导入命令**。
* 用户口述修改后，更新 `invoices.json` 并重新运行填充脚本生成 Excel。

---

### Step 8: CloudCC 一键导入与附件批量挂载

用户回复“确认导入”后，按序执行系统入库：

#### 8.1 执行导入
```bash
cloudcc reimbursement import -f <目录>/报销单批量导入_已填充.xlsx
```
从输出中解析并获取创建成功的 **报销单编号**（如 `202609227289` 或 `BX2026...`）。

#### 8.2 批量挂载发票原件附件
遍历该目录下所有发票源文件（PDF、PNG、JPG），依次执行：
```bash
cloudcc reimbursement upload-attachment -f <发票文件绝对路径> -o <报销单编号> --output json
```

#### 8.3 完成汇报
输出最终完成信息，展示报销单编号、成功上传附件列表及金额汇总。

---

### Step 9: 兼容输出（可选）
如果用户明确要求生成 CSV 文件（例如需自行留存或交付其他系统），可同时在目录下生成 `报销明细_{YYYY-MM-DD}.csv`。

## 质量检查清单

- [ ] 每条记录金额与发票面额严格一致（两位小数纯数字）。
- [ ] 差旅报销已自动关联出差单号与项目代码，非出差报销已留空 `ccsqv1`。
- [ ] 非交通发票实际发生日期已结合行程时间线推断校验。
- [ ] 滴滴行程单等补充文件已正确归并，无重复计费。
- [ ] 出差补助与住宿补助已按标准独立计算（单据数为 0，发票号为空字符串）。
- [ ] `invoices.json` 格式通过 `reimbursement-validate-invoices.py` 校验。
- [ ] Excel 文件成功生成且处于非损坏状态。
- [ ] 严格遵守在用户明确回复“确认导入”后才执行 `cloudcc reimbursement import`。
- [ ] 导入成功后自动执行附件上传，确保票据原件与单据关联。
