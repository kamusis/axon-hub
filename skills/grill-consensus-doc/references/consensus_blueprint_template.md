### 四、数据模型变更与并发控制

1. **表结构变更与 SQL 迁移**：
   - 数据库表名、新增列、数据类型与 DEFAULT 规则。
   - **严格遵循 `AGENTS.md` 规范**：
     - 无物理外键（FK）与 CHECK 约束，业务一致性在应用层校验；
     - 凡工作区作用域数据表，必须包含 `workspace_id UUID NOT NULL` 并建立索引；
     - 每张新表与新增字段必须包含 SQL `COMMENT ON` 注释（含枚举数值映射）；
     - 迁移脚本按序放置于 `server/migrations/`，严禁修改已有迁移。
2. **并发控制与数据一致性**：
   - 选用的并发控制模型（如乐观锁版本号 CAS、数据库行级锁、分布式互斥锁等）。
   - 幂等性设计（防止重复请求、多端并发写入或重复消费）。
3. **权限、隔离与安全边界**：
   - RBAC 权限 Scope 要求（如 `resource:read` / `resource:write`）。
   - 工作区多租户数据隔离防越权校验。

### 五、接口、CLI 与前端 UI 交付契约

1. **CLI 命令设计（CLI 优先原则）**：
   - 命令族与层级结构（例如 `mop <resource> <action> [args] [flags]`）。
   - 核心参数、Flags 命名、默认值规范及 `--json` 机器可读模式支持。
2. **REST API 与 WebSocket 契约**：
   - HTTP 端点：路径、请求方法、输入 Payload、输出 Response。
   - **严格遵循 API 规范**：
     - JSON 字段一律使用 camelCase；
     - 统一使用 `util.SuccessResponse` / `util.ErrorResponse` 标准响应包装；
     - 严格校验 UUID 等入参；
     - WebSocket 事件按需发布（遵从 AGENTS.md：仅通知客户端 `invalidateQueries`，绝不直接写 store）。
3. **Web UI 交互与组件规范（若涉及前端）**：
   - 优先使用 shadcn/ui 组件与语义化 Design Tokens（Tailwind CSS v4 规范）。
   - 破坏性操作必须使用 Radix UI `AlertDialog` 并在按钮绑定 `e.stopPropagation()`。
   - 所有用户可见文案必须使用 `useT("namespace")` 国际化，严禁硬编码。

### 六、全层级质量与测试验收矩阵

1. **后端单元测试 (Unit Tests)**：
   - 测试文件路径与覆盖的核心分支（业务算法、参数校验、状态跳转计算等）。
2. **服务与集成测试 (Service/Integration Tests)**：
   - 数据库事务一致性、并发读写、接口鉴权与错误码映射。
3. **端到端测试 (Playwright E2E Tests)**：
   - **严格遵循规范**：`tests/integration/` 已废弃，必须在 `tests/e2e/services/` 目录下编写测试用例。
   - 覆盖核心端到端功能闭环与关键用户交互旅程。
4. **异常与边界验收场景 (Edge Case Acceptance)**：
   - 包含故障注入、网络抖动、边界值溢出、非法输入等场景的验收标准。
